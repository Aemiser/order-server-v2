# 顺丰物流打单功能可行性调研

> 调研日期：2026-11-08
> 范围：只做可行性判定与方案设计，不含代码实现
> 目标：勾选订单 → 生成顺丰电子面单 → **一期本地打印机打印**，二期支持**云打印机**；同时支持**自定义面单编辑**

---

## 一、结论（先说结果）

**可以实现，但有三个必须先解决的硬前提，且"自定义面单编辑"的范围需要重新界定。**

| 结论项 | 判定 |
| --- | --- |
| 顺丰是否有可用官方 API 拿面单 | ✅ 有，且是官方强制路径：`COM_RECE_CLOUD_PRINT_WAYBILLS`（云打印面单打印 2.0） |
| 本地打印机打印 | ✅ 可行，有 3 条成熟路线，推荐"同步取 PDF → 本地静默打印" |
| 云打印机打印 | ✅ 可行（二期），但**顺丰不提供云打印机设备**，需接第三方云打印服务 |
| 自定义面单编辑 | ⚠️ 部分可行。可以自定义"自定义区域"（备注/商品明细/LOGO/变量文本），**不能自绘整张面单**，顺丰固定区域（条码、三段码、运单号、收寄信息）不可修改，且面单样式需过顺丰审核 |
| 现有项目能否直接加 | ⚠️ 不能直接加，需扩订单表字段 + 新增顺丰客户端 + 引入打印依赖 |

### 三个硬前提（缺一不可，都是甲方/商务侧的事，不是代码问题）

1. **顺丰开放平台企业账号 + 应用 + 顾客编码/校验码**。官方文档《开发者接入指引》明确：新用户**必须先对接云打印接口、上传云打印面单图片审核通过**，下单接口才能上线；且接口需"7 天内测试成功 3 次以上"才能点击上线。也就是说——**即使只做本地打印，也不能绕开顺丰云打印接口自己画面单**。
2. **顺丰月结卡号 / 结算方式 + 寄件人信息**。下单接口 `EXP_RECE_CREATE_ORDER` 必填 `contactInfoList`（寄件方 `contactType=1`、收件方 `=2`）、`cargoDetails`、`expressTypeId`、`orderId`；月结支付还需 `monthlyCard`。现有订单数据里这些都没有。
3. **热敏打印机 + 对应规格面单纸**（顺丰公共模板常见 `76*130`、`76*165`、丰密 `210` 等），模板规格必须和纸张一致，否则打印错位。

顺丰 API 本身**免费**（官方《开发者接入指引》"使用顺丰服务 API 目前全部免费"）。

## 二、一个必须先澄清的概念

顺丰官方文档里的「**云打印**」≠ 你要的「**云打印机**」：

- **顺丰云打印**：面单模板在顺丰云端统一管理、面单文件（PDF/指令/HTML）在云端生成，最终**仍由你本机的打印机输出**。它是**规范面单样式**的手段，不是一种打印设备。
- **云打印机**：联网的远程打印设备（快递100 云盒/云打印机、飞鹅云打印机等），无需连电脑，靠 API 远程下发任务。顺丰开放平台**没有**云打印机设备或设备绑定接口，官方插件文档明确只操作本机 `getPrinters()` / `setPrinter()` 列表。

因此正确表述是：**一期和二期都走顺丰云打印接口拿面单数据，区别只在"面单文件最终送到哪种打印机"**——这反而是好消息，二期扩展不用重做顺丰对接。

## 三、顺丰官方能力盘点（已核对官方文档）

### 3.1 网关与鉴权

| 项 | 值 |
| --- | --- |
| 生产网关 | `https://bspgw.sf-express.com/std/service` |
| 沙箱网关 | `https://sfapi-sbox.sf-express.com/std/service` |
| 生产 OAuth2 | `https://sfapi.sf-express.com/oauth2/accessToken` |
| 沙箱 OAuth2 | `https://sfapi-sbox.sf-express.com/oauth2/accessToken` |
| 报文 | HTTP POST，`application/x-www-form-urlencoded; charset=UTF-8`，`msgData` 为 JSON 字符串 |
| 公共参数 | `partnerID`（顾客编码）、`requestID`（UUID）、`serviceCode`、`timestamp`、`msgData`，认证二选一 `msgDigest` 或 `accessToken` |

**推荐用 OAuth2**（官方文档标注"推荐使用 OAuth2 方式认证"，且《标准 MD5 数字签名认证说明》原文写明"适用开发语言 JAVA，**非 JAVA 建议使用 OAuth2 方式对接**"）：

```
POST /oauth2/accessToken
partnerID=<顾客编码>&secret=<校验码>&grantType=password
→ { apiResultCode:"A1000", accessToken:"...", expiresIn:7200 }
```

token 有效期 2 小时，需缓存 + 自动刷新。本项目是 Go，走 OAuth2 可以避免 MD5 签名的坑（`Base64(MD5(URLEncoder.encode(msgData+timestamp+checkWord, UTF-8)))`，Java `URLEncoder` 与 Go `url.QueryEscape` 在 `~`、`*` 等字符上行为不一致，容易 `A1006 数字签名无效`）。

### 3.2 相关接口清单（速运 API → 面单类）

| 服务代码 | 用途 | 与本需求关系 |
| --- | --- | --- |
| `EXP_RECE_CREATE_ORDER` | 下单，返回 `waybillNoInfoList[].waybillNo` 运单号 + `routeLabelInfo` 路由标签数据 | **必接** |
| `EXP_RECE_SEARCH_ORDER_RESP` | 订单结果查询 | 建议接，做状态对账 |
| `EXP_RECE_UPDATE_ORDER` | 取消订单 | 建议接，打错单可取消 |
| `COM_RECE_CLOUD_PRINT_WAYBILLS` | **云打印面单打印 2.0 → 转 PDF** | **一期主选** |
| `COM_RECE_CLOUD_PRINT_COMMAND` | 转打印机指令 | 备选（更快的本地直打） |
| `COM_RECE_CLOUD_PRINT_HTML` | 转 HTML | 备选（前端自绘预览） |
| `COM_RECE_CLOUD_PRINT_CAINIAO` | 转菜鸟模板 | 不用 |
| `COM_RECE_CLOUD_PRINT_PARSEDDATA` | 云打印面单**打印插件**接口（JS SDK + CLodop） | 一期备选路线 |
| `COM_RECE_CLOUD_CUSTOMTEMPLATE_LIST/SAVE/DELETE` | ISV 管理商家自定义模板 | 自定义面单编辑 |

⚠️ 官方《面单打印》步骤说明原文：**"一个应用内，云打印面单接口及云打印面单插件接口只能任选一个关联"**。所以一期选了 PDF 接口，后面想改用官方插件接口需要**另建应用**；若二期走第三方云打印机，复用 PDF 接口即可，无冲突。

### 3.3 云打印面单 2.0 接口关键字段（重点）

`COM_RECE_CLOUD_PRINT_WAYBILLS`，`msgData`：

```json
{
  "templateCode": "fm_76130_standard_{partnerId}",
  "customTemplateCode": "fm_76130_standard_custom_10000022213_1",
  "version": "2.0",
  "fileType": "pdf",
  "sync": true,
  "documents": [
    { "masterWaybillNo": "SF1234567890999", "remark": "自定义区域备注",
      "customData": { "var123": "自定义变量内容" } }
  ],
  "extJson": { "mergePdf": true, "mergeType": "all", "encryptFlag": "000000" }
}
```

| 关键约束 | 说明 |
| --- | --- |
| **`sync=true` 同步** | 直接返回 `obj.files[]`：`url`（PDF 下载地址，GET）+ `token`（放请求头 `X-Auth-token`，有效期 24h）+ `waybillNo` + `seqNo` + `pageCount`。**无需公网回调地址** |
| `sync=false` 异步 | 顺丰 POST 推 `content`（Base64）到配置的回调地址。**桌面应用没有公网地址，用不了** |
| `documents` 上限 | 一批 ≤ 20 个运单，批量打印需分批 |
| `extJson.mergePdf` | 批量时合并成单个多页 PDF，一次打印作业搞定，体验最好 |
| `customTemplateCode` | 使用顺丰模板编辑器编辑的自定义区，**必须已发布且规格与主模板对应** |
| `customData` | 自定义模板里的变量值（Json 对象） |
| `remark` | 自定义区域备注，最轻量的"自定义内容" |
| 2.0 简化 | 只需传运单号，面单上的收寄信息由顺丰查订单系统自动带出，**不需要本地再拼全套字段** |
| 沙箱测试单号 | 必须先在沙箱调 `EXP_RECE_CREATE_ORDER` 拿测试运单号，不能瞎编 |

> **架构结论：本项目是 Wails 纯桌面应用（无服务端、无公网回调），必须选 `sync=true`。**

## 四、项目现状与差距

### 4.1 现有架构（`F:/project/go/order_server`）

- **Wails v2.11 桌面应用**（Go + WebView2 内嵌 Vue 3 + Vite + Element Plus），**没有 HTTP 路由**，前端通过 `app.go` 绑定的方法调后端。
- 主订单表 `go/models/addressInfo_models.go:46-56` 的 `AddressInfo` 只有：`Recipient` / `Phone` / `Address` / `ProductSpecs`(JSON) / `Remarks` + GORM `Model`。
- `ProductSpec.Weight` 单位是**斤**（`addressInfo_models.go:12`），地址是**整串未拆省市区**。
- **全项目零打印/物流代码**：`go.mod` 无任何 `printer/escpos/tspl/pdf` 依赖；前端无 lodop、无条码/二维码、无 jsPDF，唯一输出能力是 `xlsx` 导 Excel。
- 可复用资产：
  - `go/server/order/ai_model/`（DeepSeek/Qwen 地址识别）——可复用来做**地址结构化（省市区拆分）+ 重量斤→kg 换算**；
  - `go/utils/httputils/` 的超时/状态码处理风格；
  - `ReviewOrders.vue` 的 `ids []string` 批量契约 + `app.go` 的 `EventsEmit` 进度事件范式——批量勾选打印可直接照抄；
  - Element Plus `el-table type="selection"` 现成，无需引新 UI 库；
  - `cfg_*` 表配置体系（`core/init_cfg.go`）可放顺丰配置。

### 4.2 必须补的字段（建议新建 `waybill` 面单表，不要硬改 `AddressInfo`）

| 字段 | 原因 |
| --- | --- |
| `order_id`（业务单号） | 顺丰下单 `orderId` 必填、需幂等；现有只有 GORM 自增 ID |
| `waybill_no` / `branch_waybill_no` | 运单号回填、复打、查询 |
| `express_company` / `express_type_id` | 目前只顺丰，但预留扩展 |
| `print_status` / `print_count` / `printed_at` | 打印状态、防重复打单、复打 |
| `template_code` / `custom_template_code` | 面单模板选择 |
| `total_weight_kg` | 顺丰 `totalWeight` / `cargoDetails[].weight` 单位是 kg |
| `pdf_path` / `pdf_url` / `token_expire_at` | 面单文件本地缓存、复打（token 24h，PDF 需自行留存） |
| 寄件人信息 + `monthly_card` + `pay_method` | 全局配置表，不放订单行 |

并把新表加入 `go/flags/flags_db.go` 的 `AutoMigrate` 列表。

### 4.3 安全注意

顾客编码 / 校验码 / accessToken **只能放 Go 侧**（Wails 前端产物内嵌在 exe 里可被解包），前端只接收"打印结果 / PDF 预览数据"。配置放 `cfg_*` 表或本地加密 JSON，不要写进 `frontend/`。

## 五、一期方案：本地打印机打印

### 5.1 三条技术路线对比

| 路线 | 做法 | 优点 | 风险/成本 |
| --- | --- | --- | --- |
| **A. 官方插件 SDK**（`COM_RECE_CLOUD_PRINT_PARSEDDATA`） | 前端引 `SCPPrint.js`，本机装顺丰打印组件（`SCPPrint_Win32NT_6.570CN.exe`，本质 CLodop/Lodop），`print()` 直推本地打印机 | 官方维护，`getPrinters()` / `setPrinter()` 现成，支持批量、预览、A4 留底；不用自己处理 PDF 渲染 | 需在每台电脑额外装插件；**WebView2 内嵌环境下 CLodop 的本地 HTTP/WS 通信能否正常工作需 PoC 验证**；官方未承诺完全静默；一个应用只能关联插件接口或 PDF 接口之一 |
| **B. 同步取 PDF → 本地静默打印**（推荐主选） | Go 调 `COM_RECE_CLOUD_PRINT_WAYBILLS(sync=true)` → GET 下载 PDF（带 `X-Auth-token`）→ 落到本地缓存 → Go 侧静默送打印机；前端同时可预览 | 不依赖额外插件、全部 Go 可控、面单文件可留档复打、二期云打印直接复用 | 需引入 PDF 静默打印后端；热敏机纸张尺寸/缩放要调 |
| **C. 转指令 RAW 直打** | `COM_RECE_CLOUD_PRINT_COMMAND` 拿 TSPL/CPCL 指令 → Go 通过 `winspool.drv` 以 `RAW` 数据类型直发热敏机 | 速度最快、条码最清晰、无驱动缩放问题 | 该接口文档需登录控制台才能看全，指令类型/可用性**待验证**；不同品牌打印机指令集不同 |

### 5.2 推荐落地组合

**一期主选 B，同时把 C 作为可选加速路径做技术验证；A 作为兜底（若 B 的打印效果调不好，改用官方插件）。**

B 的具体实现：
1. `go/server/sfexpress/` 新建客户端（参照 `go/server/wechatorder/` 分层）：
   - `auth.go`：OAuth2 token 获取 + 2h 缓存刷新
   - `client.go`：公共参数封装、form 提交、`apiResultCode` + `apiResultData.success` 双层错误判断（**`A1000` 不代表业务成功**）
   - `order.go`：`EXP_RECE_CREATE_ORDER`、`EXP_RECE_SEARCH_ORDER_RESP`、`EXP_RECE_UPDATE_ORDER`
   - `waybill.go`：`COM_RECE_CLOUD_PRINT_WAYBILLS`，20 单分批、`mergePdf`
   - `config.go`：顾客编码、校验码、模板编码、月结卡号、寄件人、打印机名、env(sbox/pro)
2. PDF 静默打印（Windows）三选一：
   - `github.com/w6xian/printer/xprint`：`PrintPDF` 走 SumatraPDF、`PrintRaw` 走 winspool；
   - 直接 `winspool.drv` 的 `OpenPrinter/StartDocPrinter(pDatatype="RAW")/WritePrinter`；
   - 前端 WebView2 `window.print()` 只用于**预览 + 手动打印**（不能静默批量）。
3. 下载 PDF 时按 `seqNo` 排序，`mergePdf=true` 时一次作业打印多页；失败可凭本地 PDF 复打，不重复调顺丰接口。
4. 前端新增「物流打单」tab：`el-table type="selection"` 勾选 → `ids []string` 传给 Go → `EventsEmit` 回传进度（下单 1/N、取面单 1/N、打印 1/N）→ 打印前可预览 → 打印后回填运单号与状态。

### 5.3 打印链路（一期）

```
勾选订单 → 校验/补全(寄件人/重量kg/地址省市) → EXP_RECE_CREATE_ORDER 拿运单号
        → COM_RECE_CLOUD_PRINT_WAYBILLS(sync=true, mergePdf=true) 拿 PDF url+token
        → Go 下载 PDF 落本地缓存 → 静默打印到本机热敏打印机
        → 回填 waybill_no / print_status / print_count
```

## 六、自定义面单编辑：能做到什么程度

**关键限制（来自顺丰模板编辑器规则）：模板编辑界面"上下部分都是顺丰面单固定信息不支持编辑，只有在中间的可编辑区域进行自定义编辑"。** 加上"面单图片需上传顺丰审核通过"，所以**不能做整张面单的自由设计器**（自己画条码、改运单号位置、改顺丰 LOGO 都不合规）。

可行的三级做法（建议按 1→2 递进）：

| 级别 | 做法 | 工作量 |
| --- | --- | --- |
| **L1 内容级自定义**（必做） | 打印前在应用里编辑 `remark`（自定义区备注）、商品明细、客服电话等，通过 `documents[].remark` / `customData` 传给顺丰渲染 | 小 |
| **L2 模板选择 + 变量编辑**（推荐） | 顺丰控制台用官方模板编辑器建若干套已发布自定义模板（拖文本、图片、商品明细、固定字样，绑定变量）；应用内调 `COM_RECE_CLOUD_CUSTOMTEMPLATE_LIST` 列出模板，用户在「设置」里选默认模板、维护变量值（如店铺名、售后电话、活动文案），打印时传 `customTemplateCode` + `customData` | 中 |
| **L3 应用内可视化编辑器**（谨慎） | 自研拖拽编辑器，但只编辑"自定义区域"，产物映射成顺丰变量/模板；或走 `COM_RECE_CLOUD_PRINT_HTML` 取结构化数据后前端渲染预览 | 大，且预览与最终 PDF 可能不一致，需持续对齐顺丰模板版本 |

⚠️ 另一个约束：`customTemplateCode` 要求**自定义模板必须已发布，且规格要和主模板 `templateCode` 对应**。所以应用内"新建模板"最好以跳转/引导顺丰控制台完成，应用内只做"选择 + 填变量"，避免承诺做不到的能力。

## 七、二期：云打印机方案

顺丰侧**不用改**，沿用一期 `sync=true` 拿到的 PDF/图片，只是把"送本机打印机"换成"送云端设备"：

1. **设备侧**：采购支持附件打印的云打印机/云盒，例如快递100 云打印一体机/云盒（官方支持「附件打印：图片、PDF、文本」、「自定义打印模板」、打印状态回调、打印成功率 99.6%）、或飞鹅云打印机（`Open_printMsg`、`Open_queryOrderState` 等）。
2. **应用侧**：把下载的 PDF 转图片（或直接上传 PDF，视服务商支持），调用云打印 API 下发任务 + 绑定设备 SN；用服务商的 `查询订单是否打印成功 / 打印机状态` 接口做状态回写，替代本地打印结果。
3. **抽象**：一期就把打印层定义成接口，例如
   ```go
   type Printer interface {
       List() ([]PrinterInfo, error)
       Print(job PrintJob) (PrintResult, error) // PrintJob 内含 PDF 路径/图片/份数/模板
       Status(jobID string) (PrintStatus, error)
   }
   ```
   实现 `LocalPrinter`（winspool / SumatraPDF）与 `CloudPrinter`（第三方云打印 SDK），前端只切换打印机类型，**业务层零改动**。

> 若二期想改用顺丰官方插件方案而非第三方云打印机，注意前述"一个应用只能关联云打印面单接口或插件接口之一"，需要另建顺丰应用。

## 八、风险清单

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 资质/面单审核卡住 | 下单接口无法上线，整条链路跑不通 | **立项第一件事就是注册认证 + 关联 API + 沙箱联调**，不要先写业务代码 |
| 无公网回调地址 | 异步模式不可用 | 强制 `sync=true`；不要设计回调服务 |
| 面单模板规格与纸张不符 | 打印错位、审核不过 | 先定打印机型号和纸张规格，再在控制台选模板 |
| WebView2 与 CLodop 插件兼容性 | 官方插件路线可能失效 | 走路线 B（Go 侧打印），把 A 留作兜底并提前做 PoC |
| PDF 静默打印缩放/字体 | 条码扫不出、三段码变形 | 用 100% 原始尺寸、禁用"适应纸张"，打印后实扫条码验证；必要时转图片或走路线 C |
| 订单数据缺字段、地址未结构化、重量单位是斤 | 下单被拒 | 建面单表 + 复用现有 AI 做地址解析/换算，下单前做本地校验 |
| 重复打单 / 重复下单 | 产生废单、重复扣费 | `orderId` 幂等 + `print_status` 状态机 + 本地 PDF 复打优先 |
| 密钥泄露 | 账号被盗用 | 只在 Go 侧持有，前端不落任何凭据 |
| 顺丰模板版本升级 | 自定义区域变量失效 | 模板编码配置化，版本变更时只改配置 |

## 九、建议的落地顺序

0. **资质先行（商务，可能耗时最久）**：注册 `open.sf-express.com` → 企业认证 → 新建应用 → 关联 `EXP_RECE_CREATE_ORDER` / `EXP_RECE_SEARCH_ORDER_RESP` / `EXP_RECE_UPDATE_ORDER` / `COM_RECE_CLOUD_PRINT_WAYBILLS` → 配置面单模板 → 沙箱联调（7 天内成功 3 次）→ 上传面单图审核 → 上线。
1. **PoC（技术验证，1 个最小闭环）**：Go 脚本跑通 OAuth2 → 沙箱下单 → 同步取 PDF → 下载 → 本机热敏机静默打印并实扫条码。这一步通过，整个需求就判定"确定可做"。
2. **一期开发**：数据模型 → 顺丰客户端 → 打印接口抽象 + `LocalPrinter` → 勾选批量打单页 + 预览 + 进度 + 复打 → 设置页（凭据、寄件人、月结卡号、模板、打印机）。
3. **自定义编辑**：L1 内容级 → L2 模板选择 + 变量编辑。
4. **二期**：选型云打印机 → 实现 `CloudPrinter` → 状态回写。

## 十、待确认问题（需要你/顺丰客户经理回答）

1. 是否已有顺丰**月结卡号**和开放平台账号？没有的话，整个项目的时间瓶颈在审核，不在开发。
2. 现场用的是哪款热敏打印机、哪种面单纸（76×130 / 76×165 / 210 / 二联）？决定 `templateCode`。

4. 是否允许在每台装机电脑上额外安装顺丰打印组件（路线 A）？如果不允许，就锁定路线 B。
5. 二期"云打印机"是否已有设备品牌？不同厂商 API 差异较大，建议先定设备再定接口。
6. 打印时是否需要顺丰**上门取件/路由回传**，还是只要面单？（影响要关联哪些 API）
